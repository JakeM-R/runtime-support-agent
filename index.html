The support SOP the agent works to

The agent writes the drafts. These rules decide what it's allowed to send. They're the same rules as the toggles above the inbox.

Always goes to a person

  • The sender is an exec (CEO, COO, CFO…)
  • Money moved, or an agent acted without approval
  • Security, compliance or data requests, including anything asking for keys or credentials
  • Production bugs or outages (also filed to engineering)
  • Billing disputes
  • Renewal or churn language
  • An access request from someone who isn't a verified admin
  • A how-to with no help article to cite
  • Confidence below the threshold

Can be sent automatically

  • A how-to answered by a help article
  • An access request from a verified workspace admin
  • Acknowledging a feature request (logged for product, no promises)
  • A clarifying question when the ticket is too vague to act on

How replies are written

  • Lead with the answer or the next step, and when it will happen
  • Only state what a help article or the ticket supports
  • No apology padding. Sign off as Runtime Support
  • Cite the article used

How it works

The agent (drafting)

  • Reads the ticket, sorts it into a category, flags the signals in the rubric and picks a help article
  • Writes the reply and rates its confidence that the reply fully answers the ticket
  • Drafts for the 10 inbox tickets were pre-run against the rubric on 9 Nov 2026 and saved with the page
  • The page itself makes no model calls. Pasted tickets are routed by the rules, not drafted

The routing (deciding)

  • Plain rules, not the model, decide send or escalate, so the policy is explicit and testable
  • The threshold slider and rule toggles re-route the inbox live
  • Bugs get an engineering summary. Feature requests get tagged for product
  • Static page, no backend, no accounts. Source on GitHub
